# 四条旧 PR 的描述更新稿

## build #6982：IDL 输出声明与 clean 后恢复

### 相关的Issue
https://gitcode.com/openharmony/build/issues/4668

### 原因（目的、解决的问题等）
IDL 输出名称与实际文件不一致，部分 client、callback 和公共类型文件没有明确的生产者依赖，Ninja 会重复生成，清理产物后也可能因缺文件而编译失败。生成脚本每次先删除旧输出，也会使内容相同的文件更新时间戳。

### 描述（做了什么，变更了什么）
修正输出命名，补齐具体输出文件、生成目标依赖和递归 import 的 depfile。在 out 内临时生成，检查输出完整后按内容更新文件。

### 测试用例（新增、改动、可能影响的功能）
预期无改动时不重复生成，IDL 或 import 文件变化时正常重建；清理生成文件后能恢复，生成失败时保留原有输出。

## build #7046：安装依赖与输出稳定

### 相关的Issue
https://gitcode.com/openharmony/build/issues/4704

### 原因（目的、解决的问题等）
SA 依赖过滤使用追加操作，未真正排除对应文件；安装信息内容不变时仍被重写，部分可选依赖不存在，导致安装及下游 Action 重复执行。两份安装规则文件也没有声明为输入。

### 描述（做了什么，变更了什么）
修正 SA 依赖过滤，仅记录存在的可选输入；JSON 按内容比较，模块列表按内容写入，补齐空的 arm64e 输出，并将两份安装规则文件加入输入。

### 测试用例（新增、改动、可能影响的功能）
预期内容不变时保留安装信息及时间戳，规则或模块实际变化时正常更新；输出被清理后能够重新生成。

## third_party_jsframework #853：JS 构建目录与 CSS 文件依赖

### 一、内容说明（相关的 Issue）
https://gitcode.com/openharmony/third_party_jsframework/issues/323

生成的 JS 内容不变时仍被覆盖，共享 runtime 目录也会被构建过程修改；CSS 和测试输入依赖不完整，导致 gen_snapshot、ark_jsf 重复执行，清理生成目录后也可能缺少输入。

### 二、变更内容
普通和独立构建都在 out 内处理依赖副本，补齐 CSS、配置和测试文件依赖，保留 CSS 目标生成的文件。JS 内容不变时保留时间戳，并正确返回构建或测试的失败状态。

### 三、研发自测点
预期无改动时不重复生成 JS，CSS 或源码变化时正常重建；清理 out 后能够恢复，源码目录不再产生构建中间文件。

## third_party_sane-airscan #22：airscan 补丁生成目录

### 相关的Issue
https://gitcode.com/openharmony/third_party_sane-airscan/issues/19

### 原因（目的、解决的问题等）
构建时直接在源码目录应用补丁，输入源码随构建变化，声明输出也与实际文件不一致，导致 airscan_action 重复执行。旧分支还与主干新增的补丁处理发生冲突。

### 描述（做了什么，变更了什么）
保留主干现有八项补丁，在 out/gen/patched 生成副本，明确输入和输出文件，共享库使用生成副本编译；内容相同的输出不重写。

### 测试用例（新增、改动、可能影响的功能）
预期无改动时不重复打补丁或编译，清理生成目录后能够恢复，构建过程不修改源码文件。
