- heading "原因（目的、解决的问题等）" [level=3]
- paragraph: 插件和 wrapper 在源码目录生成中间文件，目录形式的输入输出不能完整表达依赖；libarkts 输出也缺少隔离，容易引起重复构建，清理后可能缺少文件。
- heading "描述（做了什么，变更了什么）" [level=3]
- paragraph: 将插件和 wrapper 放到 out 内构建，用具体文件清单声明输入输出并按内容发布，补齐 package.json 和工具依赖，隔离 libarkts 输出；清单包含主干新增的校验文件。
- heading "测试用例（新增、改动、可能影响的功能）" [level=3]
- paragraph: 预期无改动时不重复发布 SDK 文件，清理 out 后可以恢复，源码目录不再产生这些构建中间文件。
