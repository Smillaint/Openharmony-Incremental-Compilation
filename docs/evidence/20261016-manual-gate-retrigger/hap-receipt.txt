- heading "相关的Issue" [level=3]
- paragraph:
  - link "HAP 签名 Action 输出异常导致增量构建重复执行":
    - /url: https://gitcode.com/openharmony/build/issues/4663
- heading "原因（目的、解决的问题等）" [level=3]
- paragraph:
  - code: app_sign
  - text: Action 将
  - code: "${target_name}.stamp"
  - text: 声明为输出，但签名脚本不会生成该文件，同时 GN 会为目标生成同名 stamp，导致 Ninja 出现重复输出规则，并在增量构建中重复执行 HAP 签名
- paragraph:
  - text: 此外，
  - code: unsigned_hap_path_list.json
  - text: 仅记录 HAP 路径且每次直接重写，无法准确反映 unsigned HAP 内容是否发生变化，容易引起无效的下游构建传播
- heading "描述（做了什么，变更了什么）" [level=3]
- list:
  - text: 使用独立的
  - code: sign_result.json
  - text: 作为 HAP 签名 Action 输出，避免与 GN 自动生成的 target stamp 冲突。
  - listitem: 在 unsigned HAP 路径清单中增加各 HAP 文件的 SHA-256。
  - listitem: 签名完成后记录最终 HAP 路径及 SHA-256。
  - listitem: 增加文件 SHA-256 计算及原子 JSON 写入方法。
  - listitem: 输出内容未变化时保留文件时间戳；HAP 内容真实变化时仍能正常触发签名及下游构建。
- heading "测试用例（新增、改动、可能影响的功能）" [level=3]
- list:
  - listitem: 执行 Python 语法检查和补丁格式检查，检查通过。
  - listitem: 验证相同 HAP 内容重复处理时，代理输出内容及时间戳保持不变。
  - listitem: 验证 HAP 内容变化时，代理输出同步变化。
  - listitem: 执行多轮 rk3568 完整构建，构建成功。
  - listitem: HAP target stamp 重复生成警告消失。
  - listitem: 原有 10 个重复签名目标中，8 个无内容变化的目标不再重复签名；另外2个目标因 unsigned HAP 字节内容真实变化而正常向下游传播。
- paragraph:
  - text: 可能影响使用
  - code: compile_app
  - text: 和
  - code: app_sign
  - text: 模板生成、签名 HAP/HSP 的应用构建目标。
