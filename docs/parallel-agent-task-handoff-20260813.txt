五、推荐交给其他 agent 的独立任务

建议并行处理下面两个 validator Action。它们与 HAP、compile_app、packing_tool 和 native
library 追踪均不重叠。

任务 A：check_seccomp_filter_name

目标 Action：

//build/ohos/packages:check_seccomp_filter_name

已知根因：

GN 声明输出 check_seccomp_filter_name.txt，但当前校验脚本成功时不生成该文件，导致 Ninja
下一轮仍认为声明输出缺失。

接手者任务：

1. 在整仓兼容 build 基线 656fb7cf1e9efafcca30e8fd9285c312d601e9e9 上只读确认：
   - GN target 类型；
   - script；
   - outputs；
   - inputs 和 deps；
   - 最新 ninja -n -d explain 的直接 dirty 原因。
2. 找到校验脚本和已有实验提交，但不要直接复用过期分支状态。
3. 设计独立修复：
   - 校验成功时生成真实存在、内容固定的成功输出；
   - 内容不变时不刷新 mtime；
   - 使用原子写入；
   - 校验失败时仍返回非零；
   - 不伪造校验成功，不跳过真实检查。
4. 验证成功路径、重复成功路径和失败路径。
5. 使用独立分支和独立 commit，只解决该 Action。

任务 B：process_field_validate

目标 Action：

//build/ohos/packages:process_field_validate

已知根因：

GN 声明输出 cfg_validate_result.txt，但当前脚本没有生成该输出，导致 Ninja 下一轮继续认为
声明输出缺失。

接手者任务：

1. 确认 GN outputs、script、args、inputs、deps 和最新直接 dirty 原因。
2. 设计独立修复：
   - 成功时输出固定、可解释的校验结果；
   - 文件内容不变时保留 mtime；
   - 使用原子写入；
   - 校验失败时不写成功结果，并保持非零退出码；
   - 避免异常退出留下半写文件。
3. 验证：
   - 首次成功生成输出；
   - 第二次相同输入不刷新；
   - 输入非法时仍失败；
   - 失败后不会遗留虚假成功输出。
4. 使用独立分支和独立 commit，只解决该 Action。
